DynamicStage 4.5.660 - camera diagnostics only (in-app camera events reach the log)
==================================================================================
Base: 4.5.659 (tree verified identical to full-659/ + full-658/ before starting; no
partial 660 edits were present). No functional camera or stage change.

WHY 659'S LOG HAD NO CAMERA LINES (Progress.txt)
1. An app already running before it went on a card never sent its Hello while on
   the card: the Hello goes 1.5 s after the app's own launch, and SpringBoard drops a
   Hello from an app that is not on a card. So no "camera hook loaded" line.
2. Signal / Beeper / Messenger cannot write the copied log (sandbox), so their
   app-side camera658 lines never appear. Only SpringBoard and MobileSMS lines did.

WHAT CHANGED
shared/DSConstants.h
  - kDSBuildVersionString 4.5.660; kDSCamera660* names, events, flags and the
    DSCamera660Name() helper.
app/DSCameraStage.m (inside the injected apps)
  - Per-app event ring over Darwin notify: 8 slots
    "com.recreated.dynamicstage.camera660.<hash>.<k>" (state = seq | event<<16 |
    reason<<24 | flags16<<32 | extra16<<48) and a doorbell
    "com.recreated.dynamicstage.camera660.<hash>" (state = pid<<16 | latest seq).
    Slots are cleared once per process, so SpringBoard never replays old events.
  - Events: hello (cause: after launch / app saw it is staged / answer to ping),
    capture hooks in, startRunning called (path), startRunning returned, state
    (heartbeat, max every 8 s), interrupted + AVCaptureSessionInterruptionReasonKey,
    interruption ended, runtime error + code, multitask access enabled / refused,
    retry, retry cap, stop, multitask switched back off, app state change (only
    while the app has a capture session).
  - Each event carries staged / appActive / background / hooks / running /
    interrupted / multitask flags, and (read only) preview layer state: a
    connection with an AVCaptureVideoPreviewLayer, layer in a layer tree, layer has
    a size, hidden/transparent, connection enabled+active, video input present,
    plus connection and output counts.
  - Listens on "com.recreated.dynamicstage.camera660.ping.<hash>" and answers with
    a Hello (plus the old camera652-channel Hello -> camera658 "camera hook loaded").
  - DSCameraStageDidBecomeStaged(): one Hello 1 s after the stage context flips to
    staged. Skipped while SpringBoard's systemgesture state says the home / switcher
    gesture is running (retried up to 4 x 1 s).
  - Rate limits: per event kind 0.25 s (Hello 2 s per cause, State 8 s), 60 events
    a minute. All existing camera652/658 posts and behaviour are unchanged.
app/Tweak.xm
  - stagedHandler also calls DSCameraStageDidBecomeStaged() (after DSInstallHooks).
springboard/DSCameraArbiter.m
  - Watches the 5 injected bundles at arbiter start (and any bundle put on a card):
    8 check tokens + 1 doorbell each. Doorbell reads the new slots (between last
    logged seq and the doorbell's seq; new pid resets), oldest first, and writes
    "SpringBoard: camera660 <bundle> <event> ... | flags" lines. Overwritten events
    are counted in a "camera event(s) overwritten" line.
  - During the home gesture or while the system has the screen (657 no-op) the
    doorbell only marks the app dirty; one performWhenSystemTransitionOver block
    reads it afterwards (lines tagged "(read after the home / switcher gesture)").
  - noteStagedBundle (app view put on a card) pings the app 1.5 s later via
    performWhenSystemTransitionOver, max once per 3 s per app.
  - On start called / returned / retry / interrupted / runtime error / ended:
    status line (claim, published, publisher, inLayout, layoutApps, locked,
    callGuard, card, stageFg, runAssertion, scene fg/occluded/backgrounded,
    fbProcess, sbState) and the RunningBoard line (task, visible, endowments), now
    tagged camera660, floor 1 s per bundle and class (start / interrupt / other).
  - Events from an app that is not on a card: only start / interrupted / runtime
    error are noted, marked "(not on a card, full-screen camera left alone)".
  - camera658 lines (arbiter, claims, publish, hello, scene) unchanged; the shared
    log limiter is now 90 lines a minute across camera658 + camera660.
UNCHANGED: boot guard, call guard (call653), 656 call-screen hiding, 657 switcher
no-op, 659 home/wake fix, the 652 arbiter's claim / publish logic.

READING IT
  - no camera660 lines for the app after the ping line: the app's dylib is not loaded
    or notify is blocked in that app.
  - hello but no "startRunning called" when the camera opens: that camera does not use
    AVCaptureSession in this process (e.g. an extension / another process).
  - running=1 interrupted=0 and preview=attached inTree=1 sized=1 hidden=0 but black:
    frames are not reaching the layer (render / hosting side).
  - interrupted reason=1 with RunningBoard visible=0: the camera server sees the app as
    background; reason=4: multiple foreground apps.
