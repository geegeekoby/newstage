ROOT CAUSE OF items=0
STUIDataAccessStatusDomainData (SystemStatusUI, iOS 16) has NO -attributions method. "attributions"
is just the label its description prints. Its real API (iOS 16 runtime headers,
qingralf/iOS16-Runtime-Headers; matches the iOS 17 / 18.2 dumps):
  ivar STListData *_attributionListData
  -attributionListData (STListData), -dataAccessAttributions (NSArray),
  -activeAttributionData / -recentAttributionData (filtered copies).
STListData: ivar NSMutableArray *_objects, -objects, -count.
STUIDataAccessAttribution: -dataAccessType (0 audio, 1 camera, 2 location), -cameraCaptureAttribution,
  -audioRecordingActivityAttribution, -locationAttribution, -attributedEntity, -isRecent.
STAttributedEntity: -bundleIdentifier, -executableIdentity, -bundlePath.
STMediaStatusDomainCameraCaptureAttribution: -activityAttribution (STActivityAttribution: -pid).
4.5.668 asked the data object for "attributions" -> nil -> 0 items. (The 668 STListData unwrap was
right, but it never got an STListData to unwrap.)

SIGNALS (springboard/DSCameraArbiter.m)
1. Domain data (hook on -[SBSensorActivityDataProvider _handleNewDomainData:], unchanged hook):

   orderedSet/set, NSFastEnumeration, class_copyIvarList on the class chain) -> ivars of the data.
   Camera = cameraCaptureAttribution present, else dataAccessType == 1, else "type = camera" text.
   Recent-only dots skipped. Bundle = attributedEntity.bundleIdentifier (also via
   cameraCaptureAttribution.activityAttribution.attributedEntity / activeEntity, bundlePath ->
   Info.plist). Last resort: regex over the whole [data description] per STUIDataAccessAttribution
   block with "type = camera" (state active) -> bundleIdentifier.
   Confidence: high (real accessor names from class dumps, SpringBoard's own _handleNewDomainData
   uses activeAttributionData.dataAccessAttributions in the 18.2 reconstruction).
2. SpringBoard's own green-dot model: hook on -[SBSensorActivityDataProvider
   setActiveSensorActivityAttributions:] (installed only if present with a void(id) signature) plus a
   once-a-second poll of -activeSensorActivityAttributions (respondsToSelector guarded).
   SBSensorActivityAttribution: -bundleIdentifier, -sensor (0 camera / 1 microphone / 2 location per
   the 18.2 -initWithDataAccessAttribution:), -usedRecently. Camera = description says
   "sensor = camera", or sensor == 0 when the description does not name another sensor.
   Confidence: high that the methods exist on iOS 16 (in the iOS 17 header, and _handleNewDomainData:
   which we already hook is in the same class); medium on the sensor numbering for iOS 16 (from
   the 18.2 code; the one-time shape line logs it).
