2 SMOOTH MINIMISE (anim698)   off: /var/mobile/.dynamicstage-anim698-off   latch: anim698-trying/-crashed
 Causes found:
 a) Dragging toward a bottom corner sets card.cornerRadius = resting + (16 - resting) * approach on every
    pan frame. 697's "same radius = no-op" can't help (the value changes each frame), so every frame was
    a full card relayout: content mask, three rounded clips, blur-fill rounding (subview class-name walk),
    rim catcher layout, shadow. Fix: when only the radius changes (no keyboard band, bounds unchanged) the
    radius is written straight to the layers that carry it (card, content, content mask, backdrop + its
    mask/backdrop subviews, shadow) with actions off; no setNeedsLayout. Clamped to 20 like the layout.
 b) The minimise animated the REAL card's frame 420x458 -> 56x56 square past the corner (0.32 s ease-in):
    bounds animation of a view with masksToBounds corner clips, a separate CALayer mask (not view-backed:
    it got CA's own 0.25 s default animation or jumped), a UIVisualEffectView blur being resized every
    frame, the outline layer (actions disabled -> jumps), and layoutAllStackSlotsForState + chrome/keyboard
    /status-bar work inside the animation block.
    Fix: anim698FlyCard: snapshotViewAfterScreenUpdates:NO of the card (the drag already uses this API)
    is put on the window at the card's spot; the stack layout runs once WITHOUT animation (the real card
    goes straight to its off-screen corner park frame; only when that frame is off screen, else 697
    path); the snapshot gets ONE UIView animation of center + scale transform (0.30 s ease-in) -> pure GPU
    compositing, no layout/mask/blur work per frame. Completion = the same 697 finish block (state,
    hide parked cards, key window, backgrounding, icon, shelf), at the same time as before.
    Fast flick (697: card vanished instantly, "snap"): the stage still finishes at once as before, the
    snapshot flies 0.18 s ease-out to the corner (cosmetic only).
    Safety: flight is removed by stopMinimizedMotionForCard; hidden if the card is unparked mid-flight
    (completion still runs when it would have). Public UIKit/CA API only, no hooks. Scene size is not
    touched by the animation (Beeper keeps 430x931 per 695; other apps' resize still happens in the
    minimised layout exactly as in 697, now outside the animation).
 Not changed: the two-card case (other card stays: spring re-layout of the remaining card) and the
 restore animation.

3 SWEEP (perf698)   off: /var/mobile/.dynamicstage-perf698-off   latch: perf698-trying/-crashed
 Fixed:
 - Card shadow view: clear, no content -> its shadow never drew anything, but shadowOpacity 0.28 with no
   shadowPath = off-screen render pass each frame a card moves/animates. Now opacity 0 (same picture).
 - Trace "alive" heartbeat: a trace-file write every 3 s forever; now only with the verbose log
   (STALL detection unchanged). In the app dylib (sandbox can't see the verbose file) it is now off.
 - App-trace relay (Beeper/Messenger/Signal containers, ~8 stats/reads per app per poll every 1.5 s
   forever): every 6 s while none of them is on a card; full rate while one is (camera/live logic same).
 - (always on, no switch) Intro demo repeating NSTimer captured self strongly (view could never dealloc
   if stop was missed) -> weak.
 Looked at, left alone (risky or negligible), listed for later:
 - Blackout watchdog (696) ticks every 1.5 s forever; cheap early returns when no stage. Could stop when
   no card is staged, but it is also the perf-log clock.
 - DSDiagnostics run-loop observer (one store per run-loop pass) - negligible.
 - Camera arbiter 1 s timer only while claims exist (already stops).
 - noteStageGeometry still builds the 14-line summary once a second in the quiet log (rim-off-card crash
   note) - kept for crash diagnosis.
 - logStageGeometry has dead code after "return;" - harmless.
 - Pan handler per frame: refreshOutline (frame + border), facing-rim pulse, terminate glow (697 no-op
   when hidden), refreshSystemStatusBar (early-out) - all light now.
 - Corner-park frame of a minimised card is 56x56: the hosted picture for non-684 apps is shrunk to the
   card size on minimise (675 rule) -> those apps relayout on minimise/restore. Changing that is the 695
   keep-size idea applied to every app; not done (scene/keyboard risk for Messages/Signal).
