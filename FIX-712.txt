fine with NathanLR. This build adds group B only.

In this build
-------------
- Everything in 4.5.711, unchanged.
- B outside707: a touch the stage window passes through to the home screen /
  app behind, well clear of the cards (24 pt beyond the rim) and of the screen
  edges (top 44 pt, bottom 40 pt, 16 pt sides, the 86x108 bottom-corner squares),
  minimises the visible stages after 0.18 s if nothing else started meanwhile.
  Never while dragging, with a keyboard up, during / 0.8 s after a minimise or
  restore or opening the stage, during a call, while locked, during the home
  gesture / app switcher / an edge pull, or with only the picker open.
- The kbmin702 merge: kbmin702 and outside707 share one minimise path
  (minimiseVisibleStages: one card to its corner - corner707 picks a free one -,
  more cards take the home tuck; spam700-guarded). Same code as 4.5.707.

Changes from 4.5.707's outside707
---------------------------------
- hitTest does zero work with no stage on screen: after the 706 touch test says
  "not ours", it reads one BOOL (outsideArmed) and returns nil. No switch read,
  no block call, no allocation. outsideArmed is set inside the window's existing
  touch test: YES only while the stage is in overlay (on screen).
- outside707NoteTouchAt checks the stage state (and the pending flag) before its
  switch read.
- Crash latch at first use: the first touch handled with a stage open marks
  outside707-trying (removed after 15 s). 4.5.707 marked it only just before a
  minimise, so a fault in the touch path itself could never latch off.
