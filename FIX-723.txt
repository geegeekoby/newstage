WHY THE CRASH HANDLER MISSED 4.5.721
The handler (DSCrashLog) catches SIGABRT, SIGSEGV, SIGBUS, SIGILL, SIGTRAP, SIGFPE with sigaction and
no alternate signal stack (no sigaltstack / SA_ONSTACK). It cannot see:
- SIGKILL: a watchdog kill (main thread stuck / spinning, e.g. a timer or layout loop), jetsam or a
  RunningBoard termination. Uncatchable.
- A stack overflow (deep recursion): the SIGSEGV handler needs stack to run and there is none left
  without an alternate stack, so the process dies with nothing written.
A plain exception would have been SIGABRT and logged. So 721 most likely died by a watchdog kill or a
recursion stack overflow. The trace log is written in batches off the main thread, so its last lines
can be lost too; hence the synchronous breadcrumb file. Adding sigaltstack would change startup code
(not done: nothing new at load).
